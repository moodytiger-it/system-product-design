# 完整性与运行条件

每次启动先形成简短的完成定义，复用项目文档：为谁、完成什么真实任务、结果在哪里、本次交付阶段、覆盖哪些设备/语言、关键依赖与验证办法。未确认项不编造，继续独立工作。以下是判断能力是否足够的角度，不是必须增加的功能菜单。

## 基础与条件项

| 能力 | 适用范围 | 最小设计与核验 |
|---|---|---|
| 新人会用 | 新建系统默认；改造复用，局部问题按影响范围 | 开始使用、流程、第一项任务、跳过与重看；验证真实结果 |
| 日常知道做什么 | 有日常处理任务时；纯资料库用检索/最近对象即可 | 需我处理、等待他人、阻塞原因；按已有业务优先级排序，完成后队列准确变化 |
| 找回与追溯 | 有持久业务对象/结果时 | 按名称或编号找到对象，看清输入来源、必要的关键变化和当前有效版本；不强造完整审计平台 |
| 可逆与防错 | 有修改/删除/批量等改变时 | 沿用确认范围；能撤销/恢复则提供真实入口，不能撤销就说明影响；失败/重试不丢内容、不重复产生结果 |
| 登录与身份 | 本规范下的系统 | 一律飞书账号登录，不设用户名/密码或 Basic Auth；服务端按飞书 union_id 映射角色，未开通者看不到数据；回调地址、可用范围、App Secret 由 管理员配置，未配好就显示「飞书登录待开通」 |
| 权限与并发 | 多角色、敏感记录或多人编辑时 | 对象×动作的可用范围；服务端检查列表、搜索、直链、下载/导出，隐藏按钮不等于权限；并发编辑避免静默覆盖 |
| 进度与接续 | 上传/生成/导入等长任务时 | 真实阶段、最后进展、可行的重试/取消；离开可追踪，超时状态真实；取消后的最终结果不矛盾 |
| 外部数据与弱网 | 接口、同步、移动现场使用时 | 说明来源、更新时间和过期/失败状态；网络中断保留适用的输入并可恢复；不承诺未做的离线能力 |
| 运行和支持 | 承诺真实接入或部署时 | 启动/重启、配置与关键依赖位置、故障接手人、适合数据风险的恢复办法和既有反馈入口；不暴露密钥 |
| 使用效果 | 设计与建设默认定义；业务接受需实际证据 | 用户能独立完成关键任务，真实收益指标有口径；无真人试用或无观察数据时明确未验证 |

跨设备同步、通知中心、评论、工单、审批、复杂审计、离线模式和后台管理均按实际需要选用，不为了“像系统”全部加入。已有平台提供的能力直接复用。新增业务能力注明收益、范围和成本，不能暗中抬高交付范围。

## 可选能力核验举例

- 权限：授权用户完成操作；另一角色访问同一对象、搜索结果、附件/导出或直链时，实际受到相同权限限制。不使用真实越权数据做演示。
- 并发：两人或两会话修改同一版本时，后提交者得到可理解的冲突/版本处理，内容不静默消失。单人只读系统不必添加此机制。
- 恢复：用授权测试对象验证误操作恢复、必要的重启、依赖中断与重连；承诺备份恢复时实际恢复测试数据，不能凭“已配置”打勾。
- 数据时效：同步失败时展示上次成功数据及时间，不能把陈旧数据标成实时；失败不写成零数据。
- 运行交接：沿用业务 Owner、架构师及运维/支持渠道；缺接手人明确待确认。部署可访问不等于业务接受。

## 完成判断与改善

| 交付层 | 最低证据 |
|---|---|
| 设计 | 对象、流程、双端、入门和适用条件的规格可评审；假设清楚 |
| 可操作原型 | 核心操作、引导、保存范围和异常已按原型承诺验证；模拟明确 |
| 真实接入/部署 | 真实读写、权限、服务调用、部署地址、适用运行/恢复证据 |
| 业务接受 | 代表用户在承诺环境独立完成任务、结果正确，业务 Owner 的接受或明确待接受 |

阶段按原请求确定，不强迫只做原型的任务完成生产运行。逐模块说明验证状态、阻断与下一步；用户尚未确认业务接受时不能代其宣布接受，也不停止可继续完成的修复。

效果指标只选与问题相关的少量项，例如首项有效任务完成率、完成耗时、失败恢复率、重复录入减少。写口径、观察窗、数据来源和确认状态；不要把教程浏览率、漂亮截图或按钮点击数当成业务收益。优先既有日志或少量人工观察，不默认开启行为采集/外发。
