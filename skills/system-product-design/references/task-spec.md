## 关键任务卡

每条关键任务用短段或表格写清：

`使用者 → 入口 → 输入/操作 → 状态变化 → 结果对象 → 接收者/队列 → 保存与续做 → 异常恢复 → 双端差异 → 验收证据`

对象与状态复杂时再加下表：

| 对象/身份 | 关键字段与来源 | 关联对象 | 当前状态 | 动作与前置条件 | 执行者→接手者 | 新状态与结果落点 | 失败后去向 |
|---|---|---|---|---|---|---|---|
| | | | | | | | |

协作任务按需补查看/编辑/提交/审核范围；单人系统不强加审核。保存约定写明草稿/已保存/已提交的时机、存储位置及刷新/重开/换设备的结果。

## 主要页面

每个主要页面写清：谁用、核心对象、目的、布局、主/次动作、校验、加载/空/异常状态、返回位置及动作后的结果落点。网格、表格、列表、队列、画布按任务选择，不统一套卡片墙。

## 验收路径

- 成功：入口→输入→动作→反馈→结果对象→下一步。
- 异常：触发条件→反馈→修复动作→继续原任务。
- 续做：保存→离开/刷新→重开→恢复→找到最终结果。
- 交接：甲提交→乙队列→处理/退回→甲继续（适用时）。
- 入门：首次进入→理解用途与角色→自主找到第一项任务→完成→结果与下一步；另验跳过、重开与回访。
- 运行：按 [完整性与运行条件](system-readiness.md) 选验真实权限、并发、长任务、数据时效及重启/恢复，不强加无关能力。

若 AI 参与：输入来源→实际调用/模拟→输出对象→用户修订/重试→接受后进入哪个动作。

按 [验收清单](acceptance-checklist.md) 记录实际步骤与证据，未执行的项目写未验证。

如安排目标用户试用，只给任务目标并观察卡点；记录首项有效任务是否完成、耗时和需要求助处。不把设计者走通或代理模拟当真人测试。用项目已有材料记录收益指标、口径/来源和待确认项，不另建大台账。
