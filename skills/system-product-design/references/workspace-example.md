# 内容工作台：虚构设计示例

本例是用于解释交互结构的虚构场景，不描述公司的真实产品、业务数据或已验收结果。

假设一个内容团队需要选择商品和模板、编辑图文、预检、提交复核、找回结果。页面已经有这些功能，但用户需要在很长的页面上来回找输入、预览和反馈。可以在保留业务对象与规则的前提下重新组织工作。

| 维度 | 需要解决的使用障碍 | 一种可用设计 |
|---|---|---|
| 入口 | 日常任务被长介绍遮住 | 首屏呈现需我处理、最近作品或开始创作 |
| 模块 | 商品、素材、模板、作品混在同一页面 | 按检索、创作和复核任务划分模块，数量按实际需要 |
| 层级 | 编辑完后不知道回到哪里 | 对象列表→详情→工作台→结果，保留筛选和所选对象 |
| 工作台 | 输入与预览相距很远 | 电脑并排放对象、画布与属性；手机用预览和分组工具 |
| 连续性 | 切模块后丢失商品与模板 | 跨页面保留必要上下文，结果进入作品库或复核队列 |
| 电脑 | 宽屏只显示一条长表单 | 使用适合任务的并行区域、表格和详情侧栏 |
| 手机 | 关键按钮被长表单或键盘遮挡 | 分步编辑、详情返回与持续可达的主操作 |
| 表达 | 技术说明挤占业务操作 | 背景放帮助，影响决策的限制与规则放在操作附近 |

三栏和底部工具不是硬模板。照片浏览、记录处理、复核队列应根据任务选择布局，不能把这一例套到所有业务。

## 对象和状态

作品保留唯一标识、关联商品/模板、输入来源和有效版本。已生成、已保存、已提交、已复核、已导出、已发布分别建模，只有对应动作发生且有证据才改变状态。

异常路径可以是：预检发现缺资料→定位缺项→补充→返回原作品继续；协作路径可以是：编辑者提交→复核者队列找到同一作品→退回→编辑者继续。未保存离开、失败重试和重复提交按风险处理。

## 首次使用和验证

首次进入说明为谁服务、需要什么资料、第一步在哪里、结果到哪里找。快速开始直达一项真实可用任务，允许跳过和重看；回访用户直接进入日常工作。

如果只是原型，应明确本地保存、身份模拟及未接通的服务。电脑与手机都应操作到结果，验证保存→离开→重开→继续；截图、成功提示和演示数字不能替代这些检查。
