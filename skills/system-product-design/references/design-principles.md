# 系统产品设计的原则

完整执行规则见 [SKILL.md](../SKILL.md)。这份概览用于理解方法，不取代详细规格和验收证据。

## 系统如何让人持续工作

| 设计角度 | 应回答的问题 |
|---|---|
| 入口 | 我现在要做什么，从哪里开始？ |
| 核心对象 | 我处理的是哪条记录，它来自哪里、处于什么状态？ |
| 模块与层级 | 去哪里检索、看详情、编辑、处理结果，怎样返回？ |
| 任务工作台 | 输入、预览、规则与反馈怎样帮助完成这一项任务？ |
| 流程与交接 | 动作完成后结果在哪里、由谁接手、失败如何继续？ |
| 持续工作 | 保存在哪里，刷新、离开、再次进入能否继续？ |
| 电脑与手机 | 同一任务在两种设备上怎样完成，有哪些合理差异？ |
| 初次使用 | 用户能否理解用途、独立完成首项有效任务并找到下一步？ |
| 真实运行 | 适用权限、并发、时效、长任务、重启与恢复是否有证据？ |

文件数、菜单数、卡片数和手机外框不代表系统成熟度。模块依据真实任务组织，基础能力复用现有平台，额外业务能力明确收益、代价与范围。

## 承接已有项目

沿用已确认的用户、业务 Owner、架构师、目标、数据与技术栈。缺项写待确认，继续能独立完成的工作；不虚构定量目标，不重开不必要的访谈和立项。

只做设计时交付可评审设计；已要求真实保存、多人使用或部署时，不能把终点降为原型。局部修复只处理影响范围。开发授权与对外发送、付款、发布等动作的授权分别判断。

## 从第一次会用到每天好用

新建系统默认有开始使用、工作流、快速开始与稳定帮助入口。指导连到真实任务和结果，可跳过可重看；教程状态与业务状态分开。回访用户直接进入日常工作。

关键输入任务说明草稿、保存、提交、存储范围与重开行为；结果可按名称或标识找回。多人任务按真实身份校验权限，并验证提交、接手、退回和续做；单人任务不增加无关审核。

## 证据支持完成判断

设计规格、可操作原型、真实接入、软件部署和业务接受分别报告。截图说明布局，操作记录说明流程，保存回读说明结果。模拟身份、localStorage、演示动画与成功提示不能证明后台已接通。

新人与回访用户分别验收。没有真人参与时只报告独立走查。指标选择与实际问题有关的少量项，写口径、来源和观察窗；缺失不是零，也不能用教程浏览或按钮点击替代真实工作收益。
